# 科研基金申请书撰写

## 概述

科研基金申请书撰写是为联邦机构和基金会编写具有竞争力的资助申请的过程。需要掌握 NSF（美国国家科学基金会）、NIH（美国国立卫生研究院）、DOE（美国能源部）、DARPA（美国国防高级研究计划局）以及台湾 NSTC（国家科学及技术委员会）申请中各机构特定的要求、评审标准、叙述结构、预算编制和合规要求。

**关键原则：基金申请书是说服性文件，必须同时展示科学严谨性、创新性、可行性和更广泛的影响。** 每个机构都有各自不同的优先事项、评审标准、格式要求和战略目标，这些都必须得到回应。

## 何时使用本技能

在以下情况下应使用本技能：
- 为 NSF、NIH、DOE、DARPA 或 NSTC 项目撰写研究计划书
- 准备项目描述、具体目标（specific aims）或技术叙述
- 撰写更广泛影响（broader impacts）或意义陈述
- 制定研究时间表和里程碑计划
- 准备预算说明和人员分配计划
- 回应项目征集公告或资助公告
- 在重新提交时回应评审意见
- 规划多机构合作申请
- 撰写前期数据或可行性部分
- 准备个人简介（biosketch）、简历或设施描述

## 首先确定适用的资助机会

对于每项任务，记录机构、资助机会标识符及修订版本、活动/项目
类型、截止日期/时区、申请资格、提交阶段、申请表版本、
限制条件、必需附件、评审标准以及来源 URL/检索日期。除原始征集公告外，
还要检查当前的通知。已归档的征集、已资助的项目
或预算公告并不能证明当前仍有可用资助。如果无法获得官方
文件包，则提供有限范围的起草审查，并列出尚未确定的规则。

在判断合规性之前，先建立"要求 -> 来源章节 -> 草稿位置 -> 差距"矩阵。
`assets/` 中的模板是示意性工作表，而非官方表格。
切勿编造数据、引用、研究者记录、合作方承诺或批准文件。
检查最终导出的文件；Markdown 文本并不能证明符合页数要求。

对于 NIH，使用本技能处理要求梳理、评析、一致性检查，以及对研究者
撰写材料的有限编辑。[NIH 政策](https://grants.nih.gov/grants/policy/nihgps/HTML5/section_2/2.3.7_policies_affecting_applications.htm)
排除实质上由 AI 编写的申请或章节。保持申请人对实质性科学内容和写作的
主导权；仅仅进行审查或披露并不能使大量 AI 撰写变得合规。同样也要遵循其他机构的现行规则。

## 视觉增强（可选）

优秀的申请书通常包含 1–3 幅图（时间表、工作流程图、前期数据）。图表有助于评审，但不能替代清晰的目标和方法。

**图表有帮助的场景：**
- 研究方法和工作流程图
- 项目时间表或甘特图
- 概念框架或系统架构（技术类申请书）
- 实验设计流程图
- 更广泛影响活动示意图
- 在有助于阐明拟议方法时使用的 NSTC CM03 研究架构图

**如何制作图表：**
- **首选：** 使用 **scientific-schematics** 技能（`--doc-type grant`），根据自然语言描述生成 AI 示意图
- **替代方案：** 使用你常用的工具（matplotlib、Illustrator、PowerPoint 等）制作图表

示意性的可选集成（已检查 CLI 选项；本次更新未测试付费生成）。在仓库根目录下运行，并设置 `OPENROUTER_API_KEY`：

```bash
python skills/scientific-schematics/scripts/generate_schematic.py "project timeline with Year 1-3 milestones" -o figures/timeline.png --doc-type grant
```

**披露：** AI 示意图生成会将你的提示词发送到 [OpenRouter](https://openrouter.ai/)（第三方 API）。除非该传输对你的项目而言是适当的，否则不要包含未发表的敏感细节。

## 各机构概览

### NSF（美国国家科学基金会）
**使命**：促进科学进步，增进国家的健康、繁荣和福祉

**主要特点**：
- 使用[当前的 PAPPG 索引](https://www.nsf.gov/policies/pappg)、生效的补充文件和征集公告；截至审查时，NSF 24-1 由 NSF 26-200 和 26-202 补充
- 智力价值（Intellectual Merit）和更广泛影响（Broader Impacts）都会得到充分考虑；不存在通用的数值权重
- 项目描述限 15 页（大多数项目；包括"先前 NSF 资助的成果"，最多 5 页）
- 教育与社会效益，相关活动需与当前 NSF 优先事项和征集公告保持一致
- 鼓励合作研究
- 当前的 SciENcv 通用表格、研究生/博士后指导以及 Research.gov DMSP 工具要求
- 由评审小组 + 特邀评审人进行的价值评审流程

### NIH（美国国立卫生研究院）
**使命**：增进健康、延长寿命，减少疾病和残疾

**主要特点**：
- 标准 R01：具体目标最多 1 页，研究策略最多 12 页；请核实 NOFO
- 大多数 RPG 使用重要性（Importance）、严谨性/可行性（Rigor/Feasibility）以及专业能力/资源（Expertise/Resources）三项评审要素；要求的叙述标题仍为意义（Significance）、创新性（Innovation）、方法（Approach）
- 前期证据通常用于支持 R01 的可行性；请遵循具体资助机制的说明
- 严谨性与可重复性；根据 2026 年的实施方案，需使用 SciENcv 通用表格和 NIH 补充表
- 对于符合条件的申请，模块化预算以 **25,000 美元为增量**，**每个预算期的直接费用最高 250,000 美元**，不含联合体的 F&A；请核实 NOFO 和机构资格。参见 [NIH 预算指南](https://grants.nih.gov/grants/developing_budget.htm)。
- 当 NOFO 允许重新提交时，NIH 允许对未获资助的申请进行**一次重新提交（A1）**，须在初次申请截止日期后 37 个月内提交；参见[重新提交政策](https://grants.nih.gov/grants-process/submit/submission-policies/resubmission-applications)。

### DOE（美国能源部）
**使命**：通过应对能源、环境和核领域的挑战，保障美国的安全与繁荣

**主要特点**：
- 聚焦能源、气候、计算科学、基础能源科学
- 成本分摊和合作关系取决于具体办公室、NOFO 和资助工具
- 强调与国家实验室的合作
- 计算与实验的紧密结合
- 能源创新与商业化路径
- 区分 SC、ARPA-E 以及当前的应用能源办公室；原 EERE Exchange 现标识为 CMEI eXCHANGE

### DARPA（美国国防高级研究计划局）
**使命**：对用于国家安全的突破性技术进行关键投资

**主要特点**：
- 高风险、高回报的变革性研究
- 聚焦"DARPA 级难题"（如果成真会怎样，谁会在乎）
- 强调原型、演示和转化路径
- 通常需要多个阶段（可行性、开发、演示）
- 强有力的项目管理和里程碑跟踪
- 通常需要组队与合作
- 因项目经理和 BAA（广泛机构公告）不同而差异极大

### NSTC（台湾国家科学及技术委员会）
**使命**：推动台湾的科学突破、产业应用和社会影响。

**主要特点**：
- **CM03 表**：核心技术计划书格式。
- **表格**：使用当前征集和学门的表格填写中/英文摘要和 CM03。
- **创新性与可行性**：主要评审重点。
- **前期数据**：对可信度极为关键。
- **研究架构图**：在合适时有用；并非经过核实的普遍要求。

## 需要避免的常见错误

### 概念性错误

1. **未回应评审标准**：没有明确讨论意义、创新性、方法等
2. **与机构使命不匹配**：提出的研究与机构目标不一致
3. **意义不明确**：未能阐明研究为何重要
4. **创新性不足**：把渐进式工作包装成变革性工作
5. **目标模糊**：目标不具体或不可衡量

### 写作错误

1. **组织混乱**：缺乏清晰的结构和逻辑流
2. **术语过多**：更广泛的评审小组难以理解
3. **冗长啰嗦**：写作不必要地复杂或冗长
4. **缺少背景**：假设评审人对你的领域有深入了解
5. **术语不一致**：对同一概念使用不同术语

### 技术性错误

1. **方法描述不足**：细节不足以判断可行性
2. **过于雄心勃勃**：相对于时间表/预算提出的内容过多
3. **没有前期数据**：针对需要证明可行性的资助机制
4. **时间表不合理**：进度安排不现实或缺乏充分理由
5. **预算不匹配**：预算无法支撑拟议的活动

### 格式错误

1. **超出页数限制**：可能导致验证失败或不经评审即被退回
2. **字体或页边距错误**：格式不合规
3. **缺少必需章节**：申请不完整
4. **图表质量差**：图表难以辨认或不够专业
5. **引用格式不一致**：参考文献中的格式错误

### 策略性错误

1. **项目或资助机制选错**：向不合适的资助机会提交申请
2. **团队实力薄弱**：专业能力不足或缺少关键合作者
3. **缺少更广泛影响**：对于 NSF，未能充分阐述
4. **忽视项目优先事项**：与当前重点领域不一致
5. **提交过晚**：技术问题或准备仓促

## 基金申请书开发工作流程

以下时间段是规划建议，而非机构截止日期。请从经过核实的资助方截止日期
以及更早的机构内部截止日期倒推。

### 阶段 1：规划与准备（截止日期前 2-6 个月）

**活动**：
- 确定合适的资助机会
- 审阅项目公告和要求
- 咨询项目官员（如适用）
- 组建团队并确认合作关系
- 获取前期数据（如需要）
- 拟定研究计划和具体目标大纲
- 审阅成功的申请书（如有）

**产出**：
- 选定的资助机会
- 角色明确的团队
- 具体目标的初步大纲
- 所需前期数据的差距分析

### 阶段 2：起草（截止日期前 2-3 个月）

**活动**：
- 撰写具体目标或研究目标（从这里开始！）
- 编写项目描述/研究策略
- 制作图表和数据可视化
- 起草时间表和里程碑
- 准备初步预算
- 撰写更广泛影响或意义部分
- 请求支持/合作信

**产出**：
- 叙述部分的完整初稿
- 附说明的初步预算
- 时间表和管理计划
- 已向合作者请求的信函

### 阶段 3：内部审阅（截止日期前 1-2 个月）

**活动**：
- 将草稿分发给共同研究者
- 征求同事和导师的反馈
- 请求机构审查（如需要）
- 模拟评审会议（如可能）
- 根据反馈进行修改
- 完善预算和预算说明

**产出**：
- 吸收反馈后的修订稿
- 与修订计划一致的完善预算
- 已识别的弱点及应对策略

### 阶段 4：定稿（截止日期前 2-4 周）

**活动**：
- 对叙述部分进行最终修改
- 准备所有必需的表格和文件
- 敲定预算和预算说明
- 汇编个人简介、简历以及当前与待批资助（current & pending）
- 收集支持信
- 准备数据管理计划（如需要）
- 撰写项目摘要
- 校对所有材料

**产出**：
- 完整、精炼的申请书
- 所有必需的补充文件
- 符合机构要求的格式

### 阶段 5：提交（截止日期前 1 周）

**活动**：
- 机构审查和批准
- 由获授权的机构提交人通过该资助机会指定的途径上传
- 核实所有文件和格式
- 在截止日期前 24-48 小时提交
- 确认机构已收到、验证状态以及汇编后的申请
- 获取确认函和申请编号

**产出**：
- 已提交的申请书
- 提交确认
- 所有材料的存档副本

**规划提示**：为机构审批、验证和更正预留时间。48 小时缓冲是一个目标，而不是机构给予的宽限期，也不能保证注册会及时完成。能够访问公共门户并不代表能够完成需身份验证的提交。
