# Consciousness Council（心灵委员会）

这是一个结构化的练习，它模拟若干种思维原型，每种原型强调不同的假设和优先事项，然后综合它们的观点。这些是由同一个系统生成的观点，不是独立的专家或独立的证据。要将事实性主张、假设和价值判断分别标注；对会影响结论的事实性主张，要用外部来源进行核实。

## 何时使用

用于用户请求对相互竞争的优先事项或假设进行比较的场景，包括研究规划决策。输出结果是一种决策辅助工具：一个有条件的建议、尚未解决的问题，以及一个下一步行动。它不会因为达成一致意见或视角数量多就确立了科学上的有效性。

本技能在当前对话内运行。它没有随附代码、服务 API、凭证，或与 MindBook 的连接；当需要事实核验时，请使用主机可用的研究工具。不要声称它会创建托管会话、存储持久化记忆，或联系真实的专家。

## 开始审议之前

1. 说明该决策、可行的选项（相关时包括推迟决定这一选项）、限制条件，以及用户的目标。使用已提供的上下文；将重要的缺失信息明确说明为一个假设或一个问题。
2. 创建一份简短的证据简报：**既有事实**、**经外部核实的事实及来源**、**假设**、**未知事项**，以及**价值判断**。所有视角都使用同一份简报。
3. 使用原始来源或所提供的数据，核实那些可能改变建议的事实。如果无法核实，就让结论保持有条件性，并指明必须核查的内容；一个模拟出来的"实证主义者"本身不是一个信息来源。
4. 选择一个回应预算：快速（3 个视角）、标准（4–6 个），或深度（6 个）。这些数字是用来组织输出的，不是经过验证的准确性设置。

## 工作方式

委员会分三个阶段：

### 阶段 1 ——召集委员会

根据用户的问题，从下面的原型中选择 4–6 位委员会成员，除非用户要求另一种配置。要选择那些能够审视不同假设、限制条件或价值观的视角。证据所支持的一致意见也是一种有效的结果。

**12 种原型：**

| # | 原型 | 思维方式 | 提出的问题 | 盲点 |
| --- | ------------------ | ------------------------- | ------------------------------ | ------------------------------- |
| 1 | **建筑师（The Architect）** | 系统思维，结构优先 | "底层结构是什么？" | 可能对简单问题过度设计 |
| 2 | **反对者（The Contrarian）** | 反转思维，唱反调 | "如果相反的情况才是真的呢？" | 可能为了反对而反对 |
| 3 | **实证主义者（The Empiricist）** | 数据驱动，证据优先 | "证据实际上表明了什么？" | 可能忽略无法测量的东西 |
| 4 | **伦理学家（The Ethicist）** | 价值驱动，关注后果 | "谁受益、谁受损？" | 可能因道德复杂性而陷入行动瘫痪 |
| 5 | **未来学家（The Futurist）** | 长远视角，关注二阶效应 | "十年后这会是什么样子？" | 可能低估当下的现实情况 |
| 6 | **实用主义者（The Pragmatist）** | 行动导向，关注资源 | "到周五我们实际能做什么？" | 可能为了短期利益牺牲长期利益 |
| 7 | **历史学家（The Historian）** | 模式识别，关注先例 | "这种事以前是什么时候尝试过的？" | 可能用老办法打新仗 |
| 8 | **共情者（The Empath）** | 以人为中心，情感智能 | "人们实际上会对此有什么感受？" | 可能把舒适感看得比进步更重要 |
| 9 | **局外人（The Outsider）** | 跨领域，天真提问 | "为什么大家都这么假设？" | 可能缺乏领域深度 |
| 10 | **战略家（The Strategist）** | 博弈论，竞争动态 | "第二步、第三步的招法是什么？" | 可能对简单情况想得太复杂 |
| 11 | **极简主义者（The Minimalist）** | 简化，寻找约束 | "我们能去掉什么？" | 可能把复杂问题过度简化 |
| 12 | **创造者（The Creator）** | 发散思维，新颖综合 | "还有什么没试过的？" | 可能为了新颖性而牺牲可靠性 |

**选择启发法：** 将问题类型与最有生产力的张力相匹配：

- **商业决策** → 战略家 + 实用主义者 + 伦理学家 + 未来学家 + 反对者
- **技术架构** → 建筑师 + 极简主义者 + 实证主义者 + 局外人
- **个人困境** → 共情者 + 反对者 + 未来学家 + 实用主义者
- **创意挑战** → 创造者 + 局外人 + 历史学家 + 极简主义者
- **伦理问题** → 伦理学家 + 反对者 + 实证主义者 + 共情者 + 历史学家
- **策略/竞争** → 战略家 + 历史学家 + 未来学家 + 反对者 + 实用主义者

这些只是起点——要根据具体问题进行调整。目标是揭示与决策相关的权衡和证据缺口，而不是为了不一致或一致而设定配额。

### 阶段 2 ——审议

每位委员会成员按以下格式给出自己的观点：

```
🎭 [原型名称]

立场：[一句话表明立场]

理由：[用 2-4 句话，从该原型特定的视角解释其逻辑]

依据：[哪些既有/经核实的事实、假设，或价值观支持这个立场]

他们看到的关键风险：[其他人可能忽略的危险]

决策检查点：[什么证据或限制条件的改变会使这个立场改变]
```

**审议阶段的关键规则：**

- 要在假设、证据和价值观上寻求实质性的差异，但不要人为制造事实性的分歧。当证据支持一致意见时，记录下来，并审视剩余的不确定性或决策权衡。
- 即使各视角得出相同的建议，也要区分它们；避免用不同的声音重复同一个论点。
- "反对者"应检验当前领先选项背后最有力的那个假设，并且也可以得出该假设经得起审视的结论。不要编造反面证据。
- 保持每位成员发言的聚焦和锋利。深度优先于广度。

### 阶段 3 ——综合

在所有成员发言之后，给出：

```
⚖️ 委员会综合结论

共识点：[共同的结论，连同其证据和假设；仅凭一致意见本身不是一种信心信号]

核心张力：[与决策相关的权衡；若没有实质性分歧遗留，则说明这一点]

待解决的问题：[一个被忽视的问题或缺失的证据；若未发现任何此类问题，则说明这一点]

建议路径：[有条件的建议、下一步行动，以及什么会改变这个选择]

信心水平：[定性的高/中/低，附带理由，并与某个具体主张相关联；不要从投票数或言辞强度推断出一个百分比]

值得继续思考的一个问题：[用户在本次讨论之后应继续思考的问题]
```

在给出综合结论之前，要检查每一个有实质影响的事实性主张是否可以追溯到证据简报，每一条建议是否都尊重了限制条件，以及不确定性是否仍然清晰可见。一个关键的、未经核实的前提会阻止给出高信心的建议。要区分对所提议的下一步行动的信心，与对最终结果的信心。要记录有支持的一致意见和尚未解决的分歧；不要用多数投票来解决它们。

这是由代理进行的一次定性审查，不是一个自动化的验证关卡，也不能证明各项前提为真。要明确报告尚未解决的检查项。

## 委员会配置

用户可以自定义委员会：

- **"快速委员会"** 或 **"快速审议"** → 使用 3 位成员，回应更简短
- **"深度委员会"** 或 **"完整审议"** → 使用 6 位成员，推理更详细
- **"添加[某原型]"** → 纳入某个特定原型
- **"不要[某原型]"** → 排除某个特定原型
- **"自定义委员会：[列表]"** → 用户自行选定确切的成员
- **"匿名委员会"** → 在综合阶段之前使用中立的标签。这只是一种呈现方式的选项；本技能并未证实这能起到降低偏见的效果。
- **"唱反调模式"** → 用合理的失败情形对直觉选择进行压力测试，并标注假设性前提。保留经得起质疑的事实。
- **"多轮模式"** → 在最初的立场陈述之后，各成员进行第二轮相互回应

关于领域组合、可选的编辑评分，以及有边界限制的多轮或仅综合输出，参见[高级配置](references/advanced-configurations.md)。

## 什么是好的委员会问题

委员会在以下情况下效果最好：

- 存在真正的不确定性或权衡
- 存在多个都合理的视角
- 用户陷入了困境或在原地打转
- 利害关系足够重大，值得进行多角度思考
- 用户自身的偏见可能在限制其视野

在以下情况下委员会的附加价值较小：

- 有明确答案的纯事实性问题
- 用户已经做出决定、只是想要获得认可的问题
- 低风险的琐碎选择

如果某个问题看起来过于简单、不值得动用整个委员会，就直接说明——并提供一个快速的双视角对比作为替代。

## 语气和质量

- 为每个原型写出足够有特色的声音，使用户即使没有标签也能分辨出是谁在说话。
- "综合"部分应给人真正整合的感觉，而不只是列出每位成员说了什么。
- "核心张力"是综合结论中最重要的部分——它应点明用户面临的真正权衡。
- "值得继续思考的一个问题"应该真正能引发思考，而不是泛泛而谈。
- 在不刻意制造冲突的情况下保留实质性的权衡。基于证据的一致意见同样是有用的。

## 实例演练：试点研究还是完整研究

**用户："快速委员会：我们应该先做一个试点，还是直接开始完整的实验？我们有十周时间和 100 个预算单位。试点花费 20 个单位、耗时两周；完整研究花费 80 个单位、耗时八周。我们不知道我们的检测方法是否可重复。"**

这是一个虚构的、手工演练的示例，不是一个经过实验验证的结果。成本、工期和不确定性都是该情景中给定的事实。假设按顺序安排、没有重叠，并且试点将评估研究所需的检测条件。保护结果的可解释性是一个声明出来的决策优先事项，不是一个实证发现。

| 视角 | 立场与依据 | 风险与决策检查点 |
| --- | --- | --- |
| 实证主义者 | 倾向于先做试点，因为检测方法的可重复性是未知的。在观察试点结果之前，先定义适用的验收标准。 | 使用不同条件的试点可能无法回答研究本身的问题。如果已有相关的有效性验证可以解决这一不确定性，就改变这个立场。 |
| 实用主义者 | 在所陈述的假设下，先做试点再做完整研究恰好用完 100 个单位和十周时间。 | 没有为重复实验或延误留出余地。要检查截止日期和预算是否允许分阶段决策。 |
| 反对者 | 质疑这个试点是否真的能改变"做/不做"的决策；如果不能，就应该在花费这 20 个单位之前重新设计它。 | 一个令人安心的试点结果仍可能让关键的不确定性得不到解决。要明确说明什么样的结果会停止或修改完整研究。 |

**综合结论：** 三种视角都支持解决检测方法的不确定性；这种一致意见并不构成独立的证据。核心张力在于"先学习再承诺"与"不留任何时间或预算余地"之间的取舍。待解决的问题是：这个试点的验收标准能否在研究条件下真正回答可重复性的问题。建议在承诺任一路径之前，先定义这些标准和一条停止规则。对这一下一步行动的信心是中等的，而对在当前限制条件下成功完成完整研究的信心是较低的。一个值得解决的问题："哪种试点结果才会真正改变我们的决定？"

**敏感性检查：** 如果试点花费为 25 个单位，那么顺序执行的计划将花费 105 个单位，在不调整范围或预算的情况下不可行。如果已经存在相关的检测方法有效性验证，就应重新考虑是否还需要一个新的试点。即使每个原型最初都达成一致，这些变化也应该改变最终建议。

## 证据与局限性

这个具体的提示词工作流及其可选评分机制，尚未就决策准确性进行过基准测试。多智能体研究并不能直接验证在一次对话中生成的多个声音。[Baltaji 等人（2024）](https://arxiv.org/abs/2405.03862) 在其测试的协作场景中报告了人格不一致和顺从性问题。[Ferreira 等人 2026 年 9 月的一篇预印本](https://arxiv.org/abs/2609.35875) 报告称，在其小模型的实验设置中，辩论并不能可靠地胜过预算匹配的采样方法。这些有限的发现促使我们去核实证据和假设；它们并不能证明委员会练习具有普遍的益处或失败。
