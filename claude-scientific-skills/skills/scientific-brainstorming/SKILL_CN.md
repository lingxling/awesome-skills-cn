# 科学头脑风暴

## 目的与边界

使用本技能来创建、组织、质疑并透明地对候选研究方向进行优先级排序。将每一项输出都视为**提案**，而非发现。创造力方法可以改变参与度和创意产出量，但没有任何方法能普遍提升原创性、有用性或科学有效性。证据基础及其局限性概述于
`references/sources.md`。

请将以下活动区分开来：

- **创意构思（Ideation）** 产生问题、机制、替代方案或研究构想。
- **证据评估** 检查可靠的文献和数据能支持什么。
- **假设验证** 需要观察、预测、合适的设计、分析和独立审查；头脑风暴无法验证假设。
- **伦理、生物安全、两用性、监管和机构审查** 需要相关的授权审查人员。头脑风暴绝不等同于批准。
- **临床建议** 需要合格的临床医生和针对患者的具体背景。不要将研究构想转化为诊断或治疗指导。

对于由观察驱动的可检验假设，请交接给
`hypothesis-generation`。研究架构使用 `experimental-design`；
样本量使用 `statistical-power`；现有证据使用
`literature-review`；分析使用 `statistical-analysis`。

## 操作规则

1. 将论断标记为**创意**、**假设（assumption）**、**预测**、**已定位证据**或**决策**。切勿混淆这些类别。
2. 在让参与者接触他人或 AI 生成的创意之前，先进行独立生成。面对面轮流发言可能阻碍产出，而示例可能锚定后续输出。
3. 保留少数派观点、阴性证据、不确定性和弃权。共识不等于真理，票数也不是效应量。
4. 记录来源出处，但不得泄露机密、个人、受控或未发表的信息。
5. 在评分之前定义评估标准和方向。保持原始评分、理由、范围和分歧可见。
6. 在条件允许时，于**初始独立轮次之后**检索文献，然后有意重新开启创意构思。这样可以减少早期锚定，同时避免把不完整的检索误当作研究空白。
7. 不要自动选出“赢家”。评分是可追溯的决策辅助工具；定性判断、不确定性、可行性和伦理关卡仍起决定作用。

## 可复现的工作流程

### 1. 界定会议范围

写下一个核心问题，并记录：

- 目的、受众、决策负责人和时间范围；
- 范围内和范围外的主题；
- 属于真实、假定、可协商或未知的约束条件；
- 当前知识、未解决的观察结果以及禁止的输出；
- 是否可能涉及人类受试者、动物、临床护理、敏感数据、病原体、受控技术或环境释放。

如果请求涉及针对特定患者的诊疗、规避监督、有害优化或在操作层面提供助力的两用性细节，应停止创意构思，并转交至相应的专业或机构流程。

### 2. 有意识地使视角多样化

邀请相关的方法学、领域、实施、统计、安全、伦理、利益相关者和亲身经历者的视角。多样性并不保证创造力：请说明哪些人的视角已被代表、缺失或在结构上处于不利地位。在适当情况下，使用无障碍的参与方式和假名参与者 ID。

主持人应披露利益冲突，避免率先给出偏好的答案，防止资深成员主导讨论，并要求领导者在独立轮次之后再发表意见。

### 3. 独立生成

向所有人提供相同的中立提示、约束条件和固定的时间窗口。参与者在讨论前私下并行地写下创意。对于每个创意，记录：

- 稳定的 ID 和一句话陈述；
- 贡献者 ID 和阶段（`independent`、`discussion` 或 `post-check`）；
- 来源（`human`、`AI-assisted`、`literature-inspired`、`mixed` 或 `other`）；
- 假设、预测的观察结果、不确定性以及可能的反证；
- 文献启发型创意的来源标识符，以及 AI 辅助的工具/用途披露。

除非确有必要，否则在这一轮之前不要展示示例方案；如果必须展示，请将其记录为潜在锚点。

### 4. 分享而不立即评估

使用轮流发言或集中的静默分享。澄清措辞而不为之辩护。允许使用私下或匿名渠道。询问每位参与者缺少了什么、什么与主导框架相矛盾，以及听取小组意见后哪个创意变得不那么显而易见。

### 5. 结构化聚类

按照明确的关系对创意分组，例如共同的结局、机制、人群、尺度或方法。保留原始 ID 和文本。记录合并与拆分。措辞相似并不证明语义等同；当创意的假设、干预、人群或预测不同时，应保留为不同的创意。
参见 `references/facilitation_workflows.md`。

### 6. 定义透明的标准

在评分之前，定义每项标准、方向、量表锚点、所需证据、冲突以及显式权重。常见维度包括：

- 潜在的信息增益和具有区分力的预测；
- 与所界定问题的相关性；
- 相对于已检查文献（而不仅仅是相对于在场人员）的原创性；
- 可行性、资源和可逆性；
- 方法学严谨性及对偏倚的脆弱性；
- 伦理、安全、公平、两用性和监管负担；
- 当结果为阴性或与偏好的机制相矛盾时的价值。

在评估者不确定时使用范围或置信度标签。不要将否决意见隐藏在平均分之中。参见 `references/idea_evaluation.md`。

### 7. 开展对抗式评审

为每个入围创意指派一位并非其提出者的评审人。询问：

- 什么观察结果会使该创意错误或无信息量？
- 哪种替代解释能与相同的预测结果相符？
- 哪些隐藏的依赖关系、测量失败、混杂因素或选择效应可能占主导？
- 是权威、锚定、群体忠诚、发表激励还是有吸引力的技术在驱动偏好？
- 这是否可能造成伤害、加剧不平等、泄露敏感信息或助长滥用？

记录回应、缓解措施、剩余不确定性以及创意是否已被修订——而不仅仅是通过/不通过。

### 8. 检查文献和证据

检索权威数据库、原始研究、方法学指南、阴性结果以及相邻领域。在来源处核实每一条引文。对每个创意，记录检索式/日期、已筛查的来源、支持和反对的证据以及检索局限。使用诸如 `not-checked`、`search-incomplete`、`support-located`、`challenge-located` 或 `mixed` 之类的状态。

在有限检索中未发现并不能确立新颖性，而支持性文献也不能验证新的机制。在证据检查之后，重新开启一轮简短的独立生成。

### 9. 应用可行性、严谨性和伦理关卡

在推进某个创意之前，确定适当的领域审查：

- 对于生物医学工作，考虑既往研究的严谨性、稳健的设计、相关的生物学变量以及资源认证。当适用 NIH 政策时，应从研究问题到设计、分析和报告全程考虑性别作为生物学变量；用相关证据论证仅限单一性别的范围。
- 将涉及人类受试者、动物、生物安全、数据治理、出口管制、临床、环境及其他受监管的工作转交至相关办公室。
- 尽早筛查生命科学和赋能技术类创意的两用或滥用潜力。美国于 2026 年 7 月 20 日发布的《高风险生命科学政策》取代了 2024 年的 DURC/PEPP 政策；请咨询所在机构和当前的机构实施细则，而不是沿用旧的检查清单。
- 不要将敏感、未发表、专有、受控或个人信息上传到外部 AI 服务。

伦理或可行性方面的顾虑可能要求重新设计、受控处理或停止。高创造力评分绝不能凌驾于关卡之上。

### 10. 决策并记录

负责的人类决策负责人记录：

- 所考虑的候选项以及所使用的标准/权重；
- 原始评分、不确定性范围、异议、弃权和敏感性结果；
- 文献和审查日期；
- 关卡结果和所需批准；
- 决策、理由、被否决的替代方案、未解决的风险、负责人和重新审视的触发条件。

正确标注下一步行动：进一步检索、咨询、模拟、试点设计、方案制定、预注册或不采取行动。如果计划开展验证性研究，应在结果已知之前预注册假设和分析决策；对后续偏离和探索性工作要透明报告。预注册提高了透明度，但不等同于同行评审、伦理批准或有效性的证明。对于在查看现有数据集之后产生的创意，请记录哪些结局和分析此前已被看到。将在这些相同观察上进行的检验视为探索性检验；为后续的验证性检验指定新数据或未动用的留出集，而不是事后称头脑风暴已被预注册。参见 [COS guidance on existing data](https://www.cos.io/initiatives/prereg)。

## 偏倚与失败控制

- **产出阻塞（Production blocking）：** 在口头讨论之前先进行私下并行生成。
- **锚定与设计固着：** 在独立轮次之前不提供领导者的答案或 AI 示例；在证据审查之后重新开启生成。
- **权威与地位效应：** 领导者最后发言、匿名输入、独立评分以及可见的异议。
- **群体思维（Groupthink）：** 指派真正的替代方案生成角色，邀请外部审查，并记录被否决的选项。将“群体思维”视为一族风险，而非单一的、普遍确立的诊断。
- **评价顾虑：** 尽可能将贡献与署名分离；批评创意，而非贡献者。
- **过早收敛：** 设定固定的发散窗口，随后进行明确的过渡并采用预先声明的标准。
- **虚假精确：** 使用带锚点的量表、不确定性范围、敏感性分析和叙述性审查。
- **研究空白夸大：** 记录检索边界，使用“未检索到直接证据”，而不是“从未被研究过”。
- **AI 幻觉或同质化：** 人类优先的创意构思、来源出处、独立验证、多种非 AI 视角，以及对可疑重复框架的比较。参见 `references/responsible_ai.md`。

## 可选的本地 CLI

这些脚本是确定性的标准库工具。它们不调用网络服务、LLM 或科学数据库，也不得出科学结论。

```bash
python scripts/session_scaffold.py --help
python scripts/validate_register.py --help
python scripts/evaluate_matrix.py --help
```

创建会议登记表：

```bash
python scripts/session_scaffold.py \
  --session-id "microbiome-01" \
  --title "Microbiome mechanism ideation" \
  --question "Which mechanisms could explain the scoped observation?" \
  --participant P01 --participant P02 \
  --output session.json
```

验证结构和来源出处：

```bash
python scripts/validate_register.py session.json --output validation.json
```

根据 CSV 计算完全公开的加权矩阵，包括评分区间和逐一权重敏感性分析：

```bash
python scripts/evaluate_matrix.py scores.csv \
  --config criteria.json \
  --weight-delta 0.10 \
  --output matrix.json
```

输出会拒绝符号链接和已存在的文件，除非明确指定 `--force`；输入和集合大小均有界限。验证器检查的是结构，而非真伪。其检查的部分包括会议标识、创意、假设、聚类和决策引用；它不会验证每一条审查或治理记录。该矩阵将缺失的界限标记为未评估的不确定性，保留定性审查，并将 `decision` 留空。其每个创意 0–100 的评分和输入界限既不是标准平均值，也不是置信区间。输入格式和解读记录于
`references/idea_evaluation.md`。
