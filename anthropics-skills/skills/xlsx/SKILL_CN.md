# XLSX 创建、编辑和分析

| 任务 | 方法 |
|---|---|
| 带公式/格式的**创建**或**编辑** | `openpyxl`——参见下面的注意事项 |
| **批量数据**的读入或写出 | `pandas`（`read_excel`、`to_excel`） |
| **快速查看**某个工作表 | `markitdown file.xlsx`——每个工作表输出为一个 `## SheetName`；也能读取 `.xlsm`。不包含单元格坐标，所以不要据此规划编辑 |
| **读取**一个模型（公式*和*值） | 两次 `load_workbook`——参见注意事项 |

> `openpyxl`、`pandas` 和 `markitdown` 已预先安装——不要先运行 `pip install`；直接编写脚本并导入。只有当导入失败（或缺少 `markitdown` 命令）时，才用 `pip install` 安装缺失的包。

> 下文中的脚本路径都是相对于此技能目录的。

## 每个输出都必须满足的要求

- 除非用户另有说明，否则全程使用**专业字体**（Arial、Times New Roman）。
- **零公式错误。** 只要 `recalc.py` 报告 `errors_found`，就绝不交付。如果你认为某个错误在你之前就已存在，就要证明它：用 `data_only=True` 加载*原始*文件并查看那个单元格。你引入的错误和你继承的错误看起来一模一样。
- **使用公式，绝不硬编码结果。** 写 `sheet['B10'] = '=SUM(B2:B9)'`，而不是用 Python 计算出的总和。当输入发生变化时，工作表必须能重新计算。
- **严格按照用户的规格执行。** 准确的工作表标签名、准确的列标题，以及他们明确写出的公式。重新设计成计算其他东西的方案就是失败，无论它多么优雅。
- **在读者能看到的地方记录每一个假设和硬编码数字**——单元格批注，或表格末尾的相邻单元格。如果存在真实来源就注明（`Source: Company 10-K, FY2024, Page 45, Revenue Note, [SEC EDGAR URL]`）；如果数字来自用户，就直接说明。
- **由*你创建*、供他人填写的工作簿**需要一个简短的图例，说明应编辑哪些单元格，并提供一行使用真实感数值的示例行，展示预期格式。绝不要在你被要求编辑的文件中添加这样的行。
- **编辑现有文件时：完全遵循其已有约定。** 这些约定优先于此处的所有指导原则。先找到其指定的输入单元格——它们会用不同的字体颜色、填充或底纹标出——只在那里写入，并保持所有现有公式不变。

## 重新计算（只要文件包含公式就必须执行）

openpyxl 将公式写成字符串，**没有缓存值**。在你重新计算之前，对于任何读取缓存值的工具——`pandas`、
`load_workbook(data_only=True)` 以及大多数预览工具——每个公式单元格读出来都是 `None`。

```bash
python scripts/recalc.py output.xlsx [timeout_seconds]   # 默认 30
```

LibreOffice 会计算每个公式，文件会被**原地重写**，你会得到 JSON：
`status`（`success` | `errors_found`）、`total_formulas`、`total_errors`，以及一个
`error_summary`，其中每种错误类型最多列出 100 个单元格（`locations_truncated` 表示省略了多少个——
请以 `total_errors` 为准，而不是列表的长度）。修复它指出的问题后再次运行。
**如果 JSON 中出现的是 `error` 键而不是 `status`，说明什么都没有被重新计算**，而且只有这种情况下
退出码才非零——`errors_found` 的退出码是 0，所以绝不要把正常退出当作工作簿没有问题。

**重新计算通过只能证明你的公式*能求值*，而不能证明它们是*正确的*。** 区域差一位或者引用了错误的行，
会得到一个干净、无错误但数字错误的文件。在铺开整个表格之前，先写 2–3 个公式，检查它们是否取到了你预期的值。

**链接到其他文件的工作簿，如果用 openpyxl 重新保存后再重新计算，就会丢失这些链接。** 这样的公式形如
`='[1]Returns Analysis'!$B$2`——其中的 `[1]` 是工作簿外部引用列表中的索引，指向*磁盘上的另一个文件*，
而不是一个工作表。那个文件在这里很少存在，所以单元格的缓存值是唯一保存其数据的东西。openpyxl 在保存时会
去掉这个值；LibreOffice 随后不得不真正去解析该引用，失败后写入 `#NAME?`，并删除所有链接。在这种状态下
`recalc.py` 会拒绝运行——在覆盖保存之前，先从原始文件中把这些单元格的值复制出来（`--force` 可以强制运行，
即接受这种损失）。

## 选择能通过验证的公式

LibreOffice 实现的函数比 Excel 少，它无法求值的函数会变成一个字面量 `#NAME?`，固化在你交付的文件中。

- **优先使用 Excel 2007 时代的函数**——`SUMIFS`、`INDEX`、`MATCH`、`IFERROR`、`SUMPRODUCT`——它们不需要前缀。
- **有六个 2007 年之后的函数可以使用，但必须加 `_xlfn.` 前缀**，因为 openpyxl 会把你的公式原样写入 XML，而 Excel 存储 2007 年之后的函数名时会加上前缀（其界面会隐藏这个前缀）：`_xlfn.TEXTJOIN`、`_xlfn.CONCAT`、`_xlfn.IFS`、`_xlfn.SWITCH`、`_xlfn.MAXIFS`、`_xlfn.MINIFS`。如果不加前缀，每一个都会得到 `#NAME?`。
- **绝不要使用 `XLOOKUP`、`XMATCH`、`SORT`、`FILTER`、`UNIQUE` 或 `SEQUENCE`。** 运行环境中的 LibreOffice 无论加*什么*前缀都无法对它们求值。较新的版本确实能求值，但它们是溢出型数组函数，而 openpyxl 写出的文件没有溢出元数据，所以只有区域左上角的单元格会得到值——并且 `recalc.py` 会对这个被截断的结果报告 `total_errors: 0`。查找请使用 `INDEX`/`MATCH`，排序、筛选和去重请在写入单元格之前用 Python 完成。
- LibreOffice 无法解析的公式会被**转成小写**写回——这是与 `#NAME?` 并存的一个快速识别信号。

## openpyxl 注意事项

- **读取一个模型需要加载两次。** `data_only=True` 会得到缓存值，但公式没有了；默认方式会得到公式字符串，但没有值。一次加载无法同时得到两者。
- **如果保存，`data_only=True` 是破坏性的。** 那个工作簿已经没有公式了，所以保存会把每个公式都永久替换为字面值。
- **对 openpyxl 刚写出的文件使用 `data_only=True`，所有地方都会返回 `None`**——先运行 `recalc.py`。（结果为 `""` 的公式读回来也是 `None`。）
- **合并单元格：只写入左上角的锚点单元格。** 区域内的其他每个单元格都是 `MergedCell`，其 `.value` 是只读的。
- **`.xlsm` 会丢失宏，除非你向 `load_workbook` 传入 `keep_vba=True`。**
- **包含空格的工作表名称在跨表引用中必须加引号**：`='Assumptions Inputs'!$B$5`。不加引号会求值为 `#VALUE!`。

## 财务模型

除非用户另有说明，或现有文件已经采用了其他做法。

**颜色：** 蓝色文字（`0,0,255`）用于硬编码输入和情景调节参数 · 黑色用于公式 ·
绿色（`0,128,0`）用于链接到其他工作表 · 红色（`255,0,0`）用于链接到其他文件 ·
黄色填充（`255,255,0`）用于关键假设和用户应填写的单元格。

**数字：** 货币格式为 `$#,##0`，并在表头中注明单位（`Revenue ($mm)`）· 零值显示为 `-`，
百分比中也是如此（`$#,##0;($#,##0);-`）· 负数用括号表示 · 百分比格式为 `0.0%`，**以小数形式存储**
（`0.15` 显示为 `15.0%`；存储 `15` 会显示为 `1500.0%`）· 估值倍数格式为 `0.0x` · 年份用文本表示
（`"2024"`，绝不要写成 `2,024`）。

**结构：** 每个假设都放在单独的、带标签的单元格中，并由使用它的公式引用
（`=B5*(1+$B$6)`，绝不要写成 `=B5*1.05`）· 公式在每个预测期之间保持一致，因为行中间单独被修改的
某个单元格是最常见的隐蔽错误 · 对可能为零的分母做保护处理。
