# API 设计原则

掌握 REST 和 GraphQL API 设计原则，构建直观、可扩展和可维护的 API，让开发人员满意并经得起时间的考验。

## 何时使用此技能

- 设计新的 REST 或 GraphQL API
- 重构现有 API 以改进可用性
- 为您的团队建立 API 设计标准
- 在实现前审查 API 规范
- 在 API 范例之间迁移（REST 到 GraphQL 等）
- 创建开发人员友好的 API 文档
- 为特定使用情况优化 API（移动、第三方集成）

## 何时不要使用此技能

- 您只需要特定框架的实现指导
- 您正在进行仅基础设施的工作而没有 API 契约
- 您无法更改或版本化公共接口

## 说明

1. 定义消费者、用例和约束。
2. 选择 API 样式并建模资源或类型。
3. 指定错误、版本控制、分页和身份验证策略。
4. 使用示例进行验证并审查一致性。

有关详细的模式、检查清单和模板，请参阅 `resources/implementation-playbook.md`。

## 资源

- `resources/implementation-playbook.md` 获取详细的模式、检查清单和模板。

## 限制

- 仅在任务明确符合上述范围时使用此技能。
- 不要将输出视为环境特定验证、测试或专家审核的替代品。
- 如果缺少必需的输入、权限、安全边界或成功标准，请停止并要求澄清。
