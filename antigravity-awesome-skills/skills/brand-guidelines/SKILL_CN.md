# 品牌指南

按照 Sentry 的品牌指南编写面向用户的文案。

## 何时使用
- 你需要用 Sentry 的语气编写或重写面向用户的文案。
- 任务涉及 UI 文本、入职流程、空状态、文档、营销文案或其他品牌内容。
- 你需要指导何时使用简洁语言与 Sentry 语气。

## 语气选择

根据上下文选择合适的语气：

| 使用简洁语言 | 使用 Sentry 语气 |
|------------|-----------------|
| 产品 UI（按钮、标签、表单）| 404 页面 |
| 文档 | 空状态 |
| 错误消息 | 入职流程 |
| 设置页面 | 加载状态 |
| 事务性电子邮件 | "新增功能"公告 |
| 帮助文本 | 营销文案 |

**默认使用简洁语言**，除非上下文特别需要个性化。

## 简洁语言（默认）

简洁语言清晰、直接且有效。对大多数 UI 元素使用它。

### 规则

1. **简洁明了** - 使用必要的最少词数
2. **直接明确** - 告诉用户做什么，而不是他们能做什么
3. **使用主动语态** - "保存你的更改"而不是"你的更改将被保存"
4. **避免术语** - 使用用户理解的简单词汇
5. **具体明确** - "找到 3 个错误"而不是"找到一些错误"

### 示例

| 而不是 | 写 |
|------|-----|
| "单击此处保存你的更改" | "保存" |
| "你可以按日期筛选结果" | "按日期筛选" |
| "发生了错误" | "出错了" |
| "请输入有效的电子邮件地址" | "输入有效的电子邮件" |
| "你确定要删除吗？" | "删除此项？" |

## Sentry 语气

Sentry 语气在适当的时刻增添个性。它富有同情心、自我意识，偶尔还带有讽刺。

### 原则

1. **同情的讽刺** - 对情况而非用户表达挫折
2. **自我意识** - 承认软件的荒谬性
3. **有趣但实用** - 个性应增强而非掩盖意义
4. **赚取的时刻** - 仅在用户有时间欣赏时使用

### 示例

**404 页面：**
> "此页面不存在。也许它从未存在过。也许这只是一场梦。无论如何，让我们让你重新上轨道。"

**空状态：**
> "还没有错误。趁着这平静的时刻好好享受吧。"

**入职：**
> "让我们获取你的第一个错误。别担心，没有听起来那么可怕。"

**加载状态：**
> "计算中..."
> "获取你的数据..."

### 何时不使用 Sentry 语气

- 错误消息（用户感到沮丧）
- 设置页面（用户专注于工作）
- 文档（用户需要信息）
- 结账/付款流程（用户需要信任）

## 通用规则

### 拼写和语法

- 使用**美式英文**拼写（color，而非 colour）
- 对标题和页面标题使用**标题大小写**
- 对正文、按钮和标签使用**句首大小写**

### 标点符号

- UI 文本中**没有感叹号**（例外：庆祝时刻）
- 短 UI 标签或按钮文本中**没有句号**
- 完整句子和帮助文本中**使用句号**
- **不使用全大写**，除了首字母缩略词（API、SDK、URL）

### 词汇选择

| 避免 | 首选 |
|------|------|
| 请 | （省略） |
| 抱歉 | （具体说明问题） |
| 发生错误 | 出错了 |
| 无效 | （解释什么错了） |
| 成功！ | （描述发生了什么） |
| 哎哟 | （具体说明） |

## 破折号用法

| 类型 | 使用 | 示例 |
|------|------|------|
| 连字符 (-) | 复合词、范围 | "实时"、"1-10" |
| 短破折号 (--) | 范围、关系 | "2023--2024"、"父项--子项" |
| 长破折号 (---) | 中断、强调 | "错误---即使很小---也很重要" |

在大多数 UI 上下文中，使用连字符。为日期范围保留短破折号，为较长的文本保留长破折号。

## UI 元素指南

### 按钮

- 使用行动动词："保存"、"删除"、"创建"
- 具体明确："创建项目"而不仅仅是"创建"
- 尽可能最多 2-3 个词
- 没有句号或感叹号

### 错误消息

1. 说明发生了什么
2. 说明原因（如果有帮助）
3. 说明接下来要做什么

**好的：**"无法保存更改。检查你的连接并重试。"
**不好的：**"错误：保存失败。"

### 空状态

1. 解释通常在这里出现什么
2. 提供清晰的操作来填充状态
3. Sentry 语气在这里是合适的

**好的：**"还没有项目。创建你的第一个项目以开始跟踪错误。"

### 确认对话框

- 在标题中说明操作
- 如果是破坏性的，解释后果
- 使用特定的按钮标签（"删除项目"，而不是"确定"）

### 工具提示和帮助文本

- 保持在 2 句以内
- 解释"为什么"，而不仅仅是"是什么"
- 链接到复杂主题的文档

## 反面模式

避免这些常见错误：

- **机械人语言：**"项目已成功删除" -> "已删除"
- **被动语态：**"更改已保存" -> "更改已保存"
- **不必要的词汇：**"为了" -> "为"
- **犹豫：**"这可能会导致..." -> "这将导致..."
- **双否定：**"不像..." -> "类似于..."
- **UI 中的营销用语：**"超级充电你的工作流程" -> "加速你的工作流程"

## 限制
- 仅当任务清楚地符合上述范围时才使用此技能。
- 不要将输出视为环境特定验证、测试或专家评审的替代。
- 如果缺少所需的输入、权限、安全边界或成功标准，请停止并要求澄清。
