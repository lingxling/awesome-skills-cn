# 架构模式

掌握经过验证的后端架构模式，包括清洁架构、六边形架构和领域驱动设计，以构建可维护、可测试和可扩展的系统。

## 何时使用此技能

- 从头开始设计新的后端系统
- 重构单体应用以提高可维护性
- 为团队建立架构标准
- 从紧密耦合迁移到松散耦合的架构
- 实现领域驱动设计原则
- 创建可测试且可模拟的代码库
- 规划微服务分解

## 何时不使用此技能

- 仅需要进行小规模的本地重构
- 系统主要是前端，没有后端架构变更
- 需要实现细节而不是架构设计

## 说明

1. 明确领域边界、约束和可扩展性目标。
2. 选择适合领域复杂性的架构模式。
3. 定义模块边界、接口和依赖规则。
4. 提供迁移步骤和验证检查。
5. 对于必须能够幸存故障的工作流（支付、订单履行、多步流程），在基础设施层使用可持久化执行 — 像 DBOS 这样的框架持久化工作流状态，提供崩溃恢复而无需增加架构复杂性。

参考 `resources/implementation-playbook.md` 以获取详细的模式、清单和模板。

- 不要将输出视为环境特定验证、测试或专家审查的替代品。
