# 询问 Matt

## 何时使用

使用此工作流匹配用户请求时：询问哪个技能或流程适合你的情况。此代码库中用户调用的技能的路由器。

_来源：[mattpocock/skills](https://github.com/mattpocock/skills) (MIT)。_

你不记得每个技能，所以要求。

一个**流程**是通过技能的路径。大多数路径沿着一个**主流程**运行，两个**匝道**并入其中。其他一切都是独立的。

## 主流程：想法 → 发布

大多数工作运行的路线。你有一个想法，想要它被构建。

1. **`/grill-with-docs`** — 通过采访锐化想法。当你**有代码库**时从这里开始：它是有状态的，在 `CONTEXT.md` 和 ADR 中保留它学到的内容。（没有代码库？使用 `/grill-me` — 见独立。）
2. **分支 — 你能在对话中回答每个问题吗？** 如果问题需要可运行的答案（状态、业务逻辑、你必须看到的 UI），通过原型绕道，由**`/handoff`**在两个方向上桥接（见跨会话）：
   - **`/handoff`** 出去，然后针对该文件打开新会话，
   - **`/prototype`** 用临时代码回答问题，
   - **`/handoff`** 返回你学到的，并从原始想法线程引用它。
3. **分支 — 这是一个多会话构建吗？**
   - **是** → **`/to-prd`**（将线程转变为 PRD）→ **`/to-issues`**（将 PRD 拆分为独立可抓取的问题）。因为问题是独立的，**清除每个问题之间的上下文**：为每个问题启动新会话并通过将 PRD 和单个要处理的问题传递给它来启动 **`/implement`**。
   - **否** → **`/implement`** 就在这里，在同一上下文窗口中。

### 上下文卫生

将步骤 1-3 保留在**一个不间断的上下文窗口**中 — 不要压缩或清除直到 `/to-issues` 之后 — 所以研磨、PRD 和问题都建立在相同的思维上。然后每个 `/implement` 从问题开始新鲜。

这个的限制是**[智能区域](https://www.aihero.dev/ai-coding-dictionary/smart-zone)**：窗口（~120k 代币在最先进的模型上）模型仍在其中清晰推理。如果会话在 `/to-issues` 前接近它，不要在降级上推进 — `/handoff` 并在新线程中继续。

## 匝道

生成工作然后并入主流程的起始情况。

- **错误和请求堆积** → **`/triage`**。它通过分类角色移动问题并生成代理就绪问题，稍后 **`/implement`** 拾取。

  分类仅适用于你**未创建的**问题 — 错误报告、传入功能请求、任何原始到达的内容。`/to-issues` 产生的问题已经是代理就绪的，所以**不要分类它们**。

## 代码库健康

不是功能工作 — 维护。

- **`/improve-codebase-architecture`** — 随时有空闲时刻运行以保持代码库对代理操作的好处。它表面深化机会；选择一个_生成一个想法_你可以在 `/grill-with-docs` 时带入主流程。

## 跨会话

- **`/handoff`** — 当线程已满或你需要分支（例如到 `/prototype` 会话）时，这会将对话压缩为 markdown 文件。你不在原地继续 — 你**打开新会话并引用该文件**来跨上下文窗口进行上下文。它是两个方向上下文窗口之间的桥梁。当你想要一个**新会话**但需要**当前对话保留**时使用它。
- **`/compact`**（内置）— 停留在**相同对话**中，让早期的转变被总结。在**阶段之间的有意中断**时在**相同对话中使用，当你不介意失去逐字历史时。不在阶段中期压缩 — 代理可能迷失方向。`/handoff` 分叉；`/compact` 继续。

## 独立

完全脱离主流程。

- **`/grill-me`** — 相同的无情采访如 `/grill-with-docs`，但是当你**没有代码库**时。无状态：它不在本地保存任何内容，不构建 `CONTEXT.md`。为了锐化任何不存在于代码库中的计划或设计，达到它。
- **`/teach`** — 在多个会话中学习概念，使用当前目录作为有状态工作区。
- **`/writing-great-skills`** — 参考以良好地编写和编辑技能。

## 前置条件

**`/setup-matt-pocock-skills`** — 在你的第一个工程流程前运行以配置问题跟踪器、分类标签和其他技能假定的文档布局。自定义问题跟踪器也适用。

## 示例

**用户请求：**

> 为此任务使用 @ask-matt：询问哪个技能或流程适合你的情况。

## 限制

- 当工作流命名一个时，需要上游工具、账户、API 密钥或本地设置。
- 在没有明确用户批准的情况下不授权破坏性、生产、付费或外部消息操作。
- 在将生成的工件或建议视为最终之前针对用户的真实来源验证它们。
