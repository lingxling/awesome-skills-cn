# 简洁规划

## 目标

将用户请求转化为**单一、可执行的计划**，包含原子步骤。

## 工作流程

### 1. 扫描上下文

- 阅读 `README.md`、文档和相关代码文件。
- 识别约束条件（语言、框架、测试）。

### 2. 最小化交互

- 最多提出 **1-2 个问题**，且仅在真正阻塞时提出。
- 对非阻塞性的未知因素做出合理假设。

### 3. 生成计划

使用以下结构：

- **方法**：关于"做什么"和"为什么做"的 1-3 个句子。
- **范围**：用于"包括"和"不包括"的项目符号。
- **行动项**：6-10 个原子化的、有序的任务列表（动词开头）。
- **验证**：至少包含一项用于测试。

## 计划模板

```markdown
# 计划

<高级方法>

## 范围

- 包括：
- 不包括：

## 行动项

[ ] <步骤 1：发现>
[ ] <步骤 2：实现>
[ ] <步骤 3：实现>
[ ] <步骤 4：验证/测试>
[ ] <步骤 5：上线/提交>

## 开放问题

- <问题 1（最多 3 个）>
```

## 检查清单指南

- **原子化**：每个步骤应该是一个单一的逻辑工作单元。
- **动词开头**："添加..."、"重构..."、"验证..."。
- **具体**：尽可能时指定特定的文件或模块。

## 何时使用
此技能适用于执行概述中描述的工作流程或操作。

## 限制
- 仅在任务清楚地符合上述范围时使用此技能。
- 不要将输出作为环境特定验证、测试或专家审查的替代品。
- 如果缺少必需的输入、权限、安全边界或成功标准，请停止并寻求澄清。
