# 文章插图 — Grav 手绘风格

## 概览

为文章、博客文章和技术内容生成 16:9 横向手绘插图。每个插图从文章中抓取一个认知锚点，并将其转变为干净、荒诞、令人难忘的白板草图解释。

该技能使用一个称为 **Grav** 的反复出现的角色 IP：一个小的、圆形的、总是漂浮的身影，有点眼睛和细天线。Grav 参与每个插图的核心动作 — 从不只是装饰。

**代码库**：[vipin-si/article-illustrations](https://github.com/vipin-si/article-illustrations)

## 何时使用此技能

- 在需要内联插图的文章、博客文章或文档中使用
- 当你想将抽象概念转变为具体的视觉隐喻时使用
- 当你想在多篇文章中使用一致的视觉语言时使用
- 当你需要手绘解释草图而不是 PPT 信息图表时使用

## 工作原理

### 步骤 1：消化文章

阅读文章并确定认知锚点 — 核心判断、转折点、输入/输出循环、前后对比和常见陷阱。不要均匀分布插图；优先考虑受益于视觉解释的时刻。

### 步骤 2：规划镜头列表

对于每个插图，定义：
- **位置**：在哪个部分之后
- **主题**：这个图像是关于什么的
- **核心含义**：它传达的一个想法
- **结构类型**：8 种构图模式之一（工作流、系统特写、前后对比、角色状态、概念隐喻、分层方法、地图路线、迷你漫画）
- **Grav 的动作**：Grav 在场景中做什么
- **注释标签**：3-5 个短英文标签

### 步骤 3：生成图像

使用 `generate_image` 工具和内置提示模板。每个图像遵循严格的风格规则：
- 纯白背景，无纹理
- 黑色手绘线条艺术，稍微晃动
- 稀疏的红色/橙色/蓝色手写注释
- Grav 总是漂浮（从不接触表面）
- 每个图像一个核心想法
- 40-60% 画布使用，35%+ 空白

### 步骤 4：QA 检查

根据 QA 清单验证每个图像：正确格式、Grav 出现且活跃、原创隐喻、干净构图、稀疏注释、正确的颜色使用。

## 视觉风格

| 元素 | 规则 |
|:--------|:-----|
| 背景 | 纯白 — 没有奶油色、纹理、渐变或阴影 |
| 线条艺术 | 黑色、手绘、稍微晃动、不是机械的 |
| 空白 | 主要主体 40-60% 的画布，35%+ 空白 |
| 注释 | 手写英文、每个 2-5 个单词、每个图像最多 5-8 个 |
| 颜色：黑色 | 主要线条艺术、字符、结构、物体 |
| 颜色：红色 | 关键亮点、问题、警告、结果 |
| 颜色：橙色 | 主要流、路径、箭头、方向 |
| 颜色：蓝色 | 补充说明、反馈、系统状态 |
| 禁止的 | 绿色、紫色、黄色、粉红色、渐变、投影、3D、逼真 UI |

## 角色：Grav

- 小圆体（鹅卵石/土豆形）
- 两个点眼睛（略微不对称）
- 一根细弯天线，顶端有小圆圈
- 细棍腿不触碰表面摆动
- 总是悬停 — Grav 和任何表面之间可见间隙
- 表情：冷静、专注、面无表情
- 角色：系统中的主动参与者，从不装饰

## 最佳实践

- ✅ 在生成图像前以镜头列表开始
- ✅ 为每个插图创造新的隐喻 — 从不重用构图
- ✅ 让 Grav 成为行动主角，而不是旁观者
- ✅ 保持荒诞但结构清晰
- ✅ 谨慎使用颜色 — 不确定时使用黑色
- ❌ 不要制作 PPT 信息图表或正式流程图
- ❌ 不要添加标题栏或装饰框架
- ❌ 不要让 Grav 接触地面或站在表面上
- ❌ 不要让 Grav 可爱、微笑或像表情符号

## 限制

- 需要访问可以遵循构图、线条艺术和注释约束的图像生成工具。
- 反复出现的 Grav 角色风格可能在生成之间漂移；根据 QA 清单验证每个输出。
- 生成的图像中的文本可能拼写错误或扭曲，因此需要短标签和生成后审查。
- 该风格专为解释性文章插图而设计，不是逼真产品图像或品牌最终艺术作品。

## 常见陷阱

- **问题**：插图看起来像 PPT 幻灯片
  **解决方案**：删除 30% 的元素，增加空白，让它更奇怪

- **问题**：Grav 只是站在动作旁边
  **解决方案**：重新设计使 Grav 成为机制 — 成为漏斗、从杠杆摇晃、悬浮在机器内部

- **问题**：与之前插图相同的隐喻
  **解决方案**：完全替换物理对象 — 相同概念、不同类比
