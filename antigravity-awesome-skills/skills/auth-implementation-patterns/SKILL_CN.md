# 身份验证和授权实现模式

使用行业标准模式和现代最佳实践构建安全、可扩展的身份验证和授权系统。

## 何时使用此技能

- 实现用户身份验证系统
- 保护 REST 或 GraphQL API
- 添加 OAuth2/社交登录或 SSO
- 设计会话管理或 RBAC
- 调试身份验证或授权问题

## 何时不使用此技能

- 仅需要 UI 文本或登录页面样式
- 任务仅涉及基础设施，无身份问题
- 无法更改认证策略或凭据存储

## 说明

- 定义用户、租户、流程和威胁模型约束。
- 选择认证策略（会话、JWT、OIDC）和令牌生命周期。
- 设计授权模型和策略执行点。
- 规划密钥存储、轮换、日志和审计要求。
- 如果需要详细的示例，打开 `resources/implementation-playbook.md`。

## 安全性

- 永远不要记录密钥、令牌或凭据。
- 强制实施最小权限原则和密钥的安全存储。

## 资源

- `resources/implementation-playbook.md` 获取详细的模式和示例。

## 实际示例

输入：Express 应用程序接受用户的登录并保持预登录会话 ID。阅读捆绑的剧本，在凭据验证后重新生成会话，仅保存必需的身份字段，并验证旧 cookie 无法访问 `/api/profile`。同时测试失败的登录、注销和存储失败。预期：成功登录会改变会话 ID；失败的登录不授予任何访问权限。

## 输入和前置条件

记录已安装的框架/SDK 版本、身份提供商、租户模型、凭据存储和测试环境。提供项目特定的数据库适配器和请求模式；示例是集成草图，而不是可运行的身份服务。

## 限制

- JWT 验证不建立资源所有权；在读取和写入时强制执行租户和对象策略。
- 刷新轮换需要原子持久性和并发测试；仅发放示例不提供它。
- Cookie 标志不能替代 CSRF 保护，安全 cookie 行为需要针对实际 HTTPS/代理配置进行测试。
- 提供商集成和密码策略必须根据当前主要文档和应用程序的威胁模型进行检查。
