# 战略上下文检查点

在已验证的阶段后浓缩上下文，提供足够的持久信息来恢复相同任务。工具调用计数仅是提醒；它无法测量上下文质量或决定何时压缩是安全的。

## 何时使用
当探索完成、已测试的里程碑已着陆或长对话包含重复或过时的推理时使用。不要在未解决的工具调用中间、未记录的批准决定或未捕获确切证据的故障中进行压缩。

## 输入和先决条件

- 用户当前的目标、接受的约束和完成的定义。
- 当前分支和源修订、本地更改、相关工件路径和实际检查结果。
- 运行进程、待处理工具调用、批准或外部阻塞程序。
- 主机支持的上下文压缩机制。此技能不假设每个客户端都存在 `/compact`，也不操纵内部上下文文件。

## 程序

1. 选择阶段边界：从发现到实现、从实现到验证或从一个已完成批次到下一个。首先保留未解决故障的重现。
2. 协调任务状态与文件系统和 Git。区分已完成、未提交、计划和失败的工作。
3. 生成以下检查点。包括恢复所需的确切命令、结果摘要和路径；省略复制的日志和不再重要的已放弃假设。
4. 检查下一步操作是否可执行，新上下文是否不会重复合并、两次发送消息、丢失约束或覆盖无关工作。
5. 仅在已授权的项目工件中保存，或在对话中返回检查点。不要自动重写全局记忆或主机配置。
6. 如果请求并可用，使用客户端支持的压缩命令。恢复时，读取检查点并在继续前验证可变状态。

## 检查点模板

```text
目标和完成条件：
用户约束和授权边界：
源修订、分支和本地更改：
完成的结果及其验证：
未完成的工作和已知故障：
运行进程/工具标识符：
下一步所需的工件和确切路径：
下一步操作、预期结果和回退：
```

## 工作示例

对于其源 PR 在规范同步待处理时已合并的搜索功能，保留源合并 SHA、规范 PR 号和预期生成的文件。仅为实际测试的修订记录测试已通过。下一步操作是验证规范 PR 和更新的 `main`；而不是再次合并源 PR。如果浏览器检查仍然需要解锁的桌面，在继续独立代码审查时保持该条件可见。

预期结果：下一个上下文恢复未完成的验证、保留无关的本地编辑，不声称来自源合并的发布。

## 可选无状态提醒

```bash
bash skills/cc-skill-strategic-compact/suggest-compact.sh 50
```

帮助程序接受观察到的工具调用计数和可选阈值（默认 50），并在阈值处和之后每 25 次调用打印提醒。`COMPACT_TOOL_COUNT` 和 `COMPACT_THRESHOLD` 可由显式调用者适配器提供。它不存储计数器、不估计令牌使用情况、永不执行压缩。没有计数时，它会静静退出。

早期版本在无关会话中递增了共享用户状态计数器。该计数器不再被读取或写入；现有自定义包装器必须显式传递会话计数。现有状态文件保留不动。此技能不安装或编辑钩子。

## 限制
- 检查点保留记录的证据，而不是所有对话详情。当确切字节重要时保留主要工件。
- 计数是调用者提供的、有界的非负十进制整数；提醒不是上下文容量测量。
- 分支、进程和远程检查可能在检查点后更改。验证它们，而不是将摘要视为当前真实。
- 客户端上下文管理不同。不要通过删除聊天数据库、日志、缓存或项目文件来模拟压缩。
