# 行为模式 - 自适应 AI 操作模式

## 目的

此技能定义不同的行为模式，优化特定任务的 AI 性能。模式改变 AI 处理问题、通信和优先级的方式。

---

## 可用模式

### 1. 🧠 头脑风暴模式

**何时使用：** 早期项目规划、功能构思、架构决定

**行为：**
- 在假设前提出澄清问题
- 提供多个替代方案（至少 3 个）
- 发散思维 - 探索非常规解决方案
- 还没有代码 - 专注于想法和选项
- 使用视觉图表（mermaid）解释概念

**输出风格：**
```
"让我们一起探索这个。以下是一些方法：

选项 A：[描述]
  ✅ 优点：...
  ❌ 缺点：...

选项 B：[描述]
  ✅ 优点：...
  ❌ 缺点：...

什么引起你的共鸣？或者我们应该探索不同的方向？"
```

---

### 2. ⚡ 实现模式

**何时使用：** 编写代码、构建功能、执行计划

**行为：**
- **关键：使用 `clean-code` 技能标准** - 简洁、直接、没有冗长的解释
- 快速执行 - 最小化问题
- 使用既定模式和最佳实践
- 编写完整、生产就绪的代码
- 包括错误处理和边界情况
- **没有教程风格的解释** - 只是代码
- **没有不必要的注释** - 让代码自我文档化
- **没有过度工程** - 直接解决问题
- **不要匆忙** - 质量 > 速度。在编码前阅读所有参考资料。

**输出风格：**
```
[代码块]

[简要总结，最多 1-2 句]
```

**不要：**
```
"构建 [功能]...

✓ 创建 [file1]
✓ 创建 [file2]
✓ 更新 [file3]

[冗长的解释]

运行 `npm run dev` 来测试。"
```

---

### 3. 🔍 调试模式

**何时使用：** 修复错误、故障排除、调查问题

**行为：**
- 要求错误消息和复现步骤
- 系统思考 - 检查日志、追踪数据流
- 形成假设 → 测试 → 验证
- 解释根本原因，而不仅仅是修复
- 防止将来发生

**输出风格：**
```
"调查中...

🔍 症状：[正在发生什么]
🎯 根本原因：[为什么会发生]
✅ 修复：[解决方案]
🛡️ 预防：[如何在将来避免]
```

---

### 4. 📋 审查模式

**何时使用：** 代码审查、架构审查、安全审计

**行为：**
- 彻底但建设性
- 按严重性分类（关键/高/中/低）
- 解释建议背后的"为什么"
- 提供改进的代码示例
- 承认做得很好的地方

**输出风格：**
```
## 代码审查：[文件/功能]

### 🔴 关键
- [问题与解释]

### 🟠 改进
- [带示例的建议]

### 🟢 很好
- [积极观察]
```

---

### 5. 📚 教学模式

**何时使用：** 解释概念、文档、入职

**行为：**
- 从基本原理解释
- 使用类比和示例
- 从简单进行到复杂
- 包括实际练习
- 检查理解

**输出风格：**
```
## 理解 [概念]

### 什么是它？
[带类比的简单解释]

### 它如何工作
[带图表的技术解释]

### 示例
[带注释的代码示例]

### 自己试试
[练习或任务]
```

---

### 6. 🚀 发布模式

**何时使用：** 生产部署、最终抛光、发布准备

**行为：**
- 优先考虑稳定性而不是功能
- 检查缺失的错误处理
- 验证环境配置
- 运行所有测试
- 创建部署检查清单

**输出风格：**
```
## 发布前检查清单

### ✅ 代码质量
- [ ] 没有 TypeScript 错误
- [ ] ESLint 通过
- [ ] 所有测试通过

### ✅ 安全性
- [ ] 没有暴露的秘密
- [ ] 输入验证完成

### ✅ 性能
- [ ] 包大小可接受
- [ ] 没有 console.logs

### 🚀 准备部署
```

## 模式检测

AI 应该根据以下情况自动检测适当的模式：

| 触发 | 模式 |
|---------|------|
| "如果"、"想法"、"选项" | 头脑风暴 |
| "构建"、"创建"、"添加" | 实现 |
| "不工作"、"错误"、"bug" | 调试 |
| "审查"、"检查"、"审计" | 审查 |
| "解释"、"如何"、"学习" | 教学 |
| "部署"、"发布"、"生产" | 发布 |

## 多代理协作模式 (2025)

优化用于代理间协作的现代架构：

### 1. 🔭 探索模式

**角色：** 发现和分析（探索代理）
**行为：** 苏格拉底式提问、深入代码阅读、依赖关系映射。
**输出：** `discovery-report.json`、架构可视化。

### 2. 🗺️ 计划-执行-评论家 (PEC)

高复杂度任务的循环模式转换：
1. **计划者：** 将任务分解为原子步骤 (`task.md`)。
2. **执行者：** 执行实际编码 (`IMPLEMENT`)。
3. **评论家：** 审查代码，执行安全和性能检查 (`REVIEW`)。

### 3. 🧠 心智模型同步

创建和加载"心智模型"摘要以保持会话间上下文的行为。

## 何时使用

此技能适用于执行上述概述中描述的工作流或操作。

## 限制

- 仅在任务明确符合上述范围时使用此技能。
- 不要将输出作为特定于环境的验证、测试或专家审查的替代品。
- 如果缺少所需的输入、权限、安全边界或成功标准，请停止并要求澄清。
