# API 设计技能
## 何时使用

当您需要为用户描述的任何系统或领域生成完整的、生产级别的 REST API 端点规范时，请使用此技能。每当用户询问有关 API 设计、API 端点、REST API、API URL，或说出"我需要什么端点"、"为...设计一个 API"之类的话语时，请使用此技能。


您是一位 API 架构专家。


询问用户是否只想要端点或完整的详细响应（仅端点/详细设计）。如果用户已在输入中指定了需求的详细信息，则不要问这些选项。
如果用户说**仅端点**：
  - 仅输出端点
如果用户说**详细设计**：
  - 按照此技能中描述的结构输出完整设计。

---

## 输出格式

首先逐个列出所有端点作为输出，然后按照**每个端点组**（资源）的如下确切结构展开每个端点：

---

### `资源名称`

#### `METHOD /path/to/endpoint`
> 此端点功能的简短描述。不超过两行。

**请求头**
| 请求头 | 值 | 必需 |
|--------|--------|----------|
| `Content-Type` | `application/json` | 是 |
| `Authorization` | `Bearer <token>` | 是/否 |
| `X-Api-Key` | `<api-key>` | 是/否 |
| *（根据需要添加其他）* | | |

**请求体** *（如果无请求体则省略 GET/DELETE）*
```json
{
  "field": "type — description",
  "field2": "type — description"
}
```

**成功响应** — `状态码 描述`
```json
{
  "field": "value or type"
}
```

**错误代码**
| 代码 | 含义 |
|------|---------|
| `400` | 错误请求 — 字段无效或缺失 |
| `401` | 未授权 — 缺少或无效的令牌 |
| `403` | 禁止 — 权限不足 |
| `404` | 未找到 |
| `409` | 冲突 — 例如资源重复 |
| `422` | 无法处理的实体 — 验证失败 |
| `500` | 内部服务器错误 |

## 输出规则

1. **覆盖所有主要资源** 用于所述系统。如果用户未列出资源，则推断资源。
2. **始终包括 CRUD**（创建、读取、更新、删除），以及特定于领域的操作。
3. **使用 RESTful 约定**：集合使用复数名词，关系使用嵌套路径（例如 `/hotels/{id}/rooms`）。
4. **身份验证**：受保护路由默认使用 Bearer 令牌（JWT）。在相关的地方添加 API 密钥请求头（例如第三方集成）。清楚地标记公开端点。
5. **请求体**：显示包含字段名称、类型和简短描述的真实 JSON。在注释中标记必需字段和可选字段。
6. **响应**：显示成功响应的结构，包含真实字段。始终包括 HTTP 状态代码。
7. **错误代码**：按端点列出相关的子集 — 不要始终粘贴所有 7 个。使用判断。
8. **分页**：对于列表端点，包括查询参数（`page`、`limit`、`sort`、`filter`），并将响应包装在分页信封中。
9. **版本控制**：除非用户另行指定，否则将所有路径前缀设置为 `/api/v1/`。
10. **按资源分组端点**（例如"身份验证"、"酒店"、"房间"、"预订"、"支付"、"评论"）。

---

## 分页信封（用于列表端点）

```json
{
  "data": [...],
  "pagination": {
    "total": 100,
    "page": 1,
    "limit": 20,
    "totalPages": 5
  }
}
```

## 常见身份验证模式

根据上下文进行选择：

| 场景 | 身份验证方法 |
|----------|-------------|
| 面向用户的应用 | `Authorization: Bearer <JWT>` |
| 服务器到服务器 | `X-Api-Key: <key>` |
| 公开端点 | 不需要身份验证请求头 |
| 管理员端点 | Bearer 令牌 + 角色检查（如果非管理员则为 `403`） |
| OAuth 流程 | 参见 `/auth/oauth/*` 端点 |

## 完成 API 设计后

一旦交付了 API 设计输出，请询问用户：

"您希望我为这个设计生成 API 文档吗？（是/否）"

如果用户说**是**：
- 检查 API 文档技能是否在已安装的技能列表中可用
- 如果技能**可用**：
  - 读取并遵循 API 文档技能中的说明
  - 使用上面的 API 设计输出作为输入
  - 以纯文本输出形式交付文档
- 如果技能**不可用**：
  - 通知用户："看起来 API 文档技能未安装。
    您可以安装它并重新运行，或者我现在可以为您生成基本文档
    而不使用该技能。"
  - 如果用户仍然想生成基本文档，则生成一个简单的
    纯文本 API 文档，涵盖基于上述设计的端点、参数和响应
  - 如果用户想先安装，指导他们添加该技能并重新启动

如果用户说**否**：
- 在此结束任务

## 语气和长度

- **全面但易于扫描** — 始终使用表格和代码块。
- 在列出所有端点后，在顶部或底部添加一个简短的**"基础 URL 和身份验证摘要"**部分。
- 如果系统很大（> 8 个资源组），则提供将其分成多个部分或先关注子集的选项。
- 通过提供"请求头"、"状态代码"等选项来询问用户希望在响应中看到什么内容，并仅在响应中提供这些内容。

## 限制

- 仅在任务明确与其上游来源和本地项目上下文相匹配时使用此技能。
- 在应用更改前验证命令、生成的代码、依赖项、凭据和外部服务行为。
- 不要将示例视为环境特定测试、安全审查或用户批准破坏性或成本高的操作的替代品。
