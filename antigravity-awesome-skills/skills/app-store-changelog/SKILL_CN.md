# 应用商店更新日志

## 概览

从最后一个标签之后的 git 历史生成全面的用户面向的更新日志，然后将提交转换为清晰的应用商店发布说明。

## 何时使用

- 当用户要求应用商店"新增内容"文本或来自 git 历史的发布说明时。
- 当需要将原始提交转换为简洁的用户面向的项目符号时。

## 工作流

### 1) 收集变更

- 从代码库根目录运行 `scripts/collect_release_changes.sh` 以收集提交和修改的文件。
- 如果需要，传递特定标签或引用：`scripts/collect_release_changes.sh v1.2.3 HEAD`。
- 如果不存在标签，脚本将回退到完整历史。

### 2) 用户影响分类

- 扫描提交和文件以识别用户可见的变更。
- 按主题（新增、改进、修复）分组变更并去除重复。
- 删除仅限内部的工作（构建脚本、重构、依赖项更新、CI）。

### 3) 起草应用商店说明

- 为每个用户面向的变更编写简短的、以利益为中心的项目符号。
- 使用清晰的动词和简洁的语言；避免内部术语。
- 除非用户要求其他长度，否则偏好 5 到 10 个项目符号。

### 4) 验证

- 确保每个项目符号都映射回范围内的真实变更。
- 检查是否有重复项和过于技术性的措辞。
- 如果任何变更不明确或可能仅限内部，请要求澄清。

## 提交到项目符号示例

以下显示原始提交如何转换为应用商店项目符号：

| 原始提交消息 | 应用商店项目符号 |
|---|---|
| `fix(auth): resolve token refresh race condition on iOS 17` | • 修复了登录问题，该问题可能导致某些用户意外退出。 |
| `feat(search): add voice input to search bar` | • 使用新的语音输入选项免提搜索你的库。 |
| `perf(timeline): lazy-load images to reduce scroll jank` | • 滚动你的时间线现在更流畅和快速。 |

**删除**的仅限内部提交（无用户影响）：
- `chore: upgrade fastlane to 2.219`
- `refactor(network): extract URLSession wrapper into module`
- `ci: add nightly build job`

## 示例输出

```
3.4 版本新增功能

• 使用新的语音输入选项免提搜索你的库。
• 滚动你的时间线现在更流畅和快速。
• 修复了登录问题，该问题可能导致某些用户意外退出。
• 为设置屏幕添加了深色模式支持。
• 改进了打开大型照片相册时的加载时间。
```

## 输出格式

- 标题（可选）："新增内容"或产品名称 + 版本。
- 仅项目符号列表；每个项目符号一句话。
- 如果用户提供了一个，请遵守商店限制。

## 资源

- `scripts/collect_release_changes.sh`：从最后一个标签之后收集提交和修改的文件。
- `references/release-notes-guidelines.md`：应用商店说明的语言、过滤和 QA 规则。

## 限制

- 仅当任务明确匹配上述范围时才使用此技能。
- 不要将输出视为环境特定验证、测试或专家审查的替代品。
- 如果缺少必需的输入、权限、安全边界或成功标准，请停止并要求澄清。
